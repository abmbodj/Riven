# Riven — Study Groups Feature
### Complete Feature Documentation

---

## Overview

Study Groups is a collaborative feature that lets students in the same class share decks, files, and study sessions inside Riven. It introduces a social layer to the app, making studying a shared experience rather than a solitary one.

**Access:** Free for all users
**Version:** v1

---

## Core Concept

A student creates a group, links it to a class, and shares a 6-character join code with classmates. Inside the group, members share flashcard decks, upload and organize files into folders, and join live group cram sessions. Everything is tied to the class it belongs to, keeping the experience focused and academic.

---

## Creating a Group

Student taps the Study Groups entry point and creates a new group:

```
Group Name:   Bio 101 Squad
Linked Class: Biology
Join Code:    RIV-4X2        ← auto-generated by Riven
Members:      1 (just you)
```

The join code is automatically generated — 6 characters, always prefixed with RIV for brand consistency. The group creator becomes the admin.

---

## Joining a Group

Any Riven user can join a group by entering the join code. No email invites, no approval flow, no friction.

```
Join a Group
─────────────────────────
Enter group code:
[ R I V - 4 X 2 ]

[Join Group]
```

Once joined, the student immediately sees all shared decks, files, and active cram sessions.

---

## Inside a Group

Every group has three sections:

```
Bio 101 Squad
Biology · 4 members · Midterm in 6 days

[ Shared Decks ]  [ Shared Files ]  [ Cram Session ]
```

---

## Section 1 — Shared Decks

Any member can add an existing deck from their personal library to the group. Once shared, every group member can study from it.

**How it works:**
- Member taps "Add Deck" and selects from their personal library
- Deck appears in the group's Shared Decks list
- All members can open and study the deck
- The original owner retains ownership — deleting from personal library removes it from the group
- Any member can remove a deck they personally shared

**What it looks like:**
```
Shared Decks
─────────────────────────
📚 Ch. 4 Key Terms        42 cards · shared by Maya
📚 Enzyme Functions       28 cards · shared by James
📚 Preterite SER & IR     18 cards · shared by you

[+ Add a Deck from your Library]
```

**Studying a shared deck** uses the same study mode, spaced repetition, and cram mode already in Riven. Progress is personal — each member's SRS data is their own, not shared.

---

## Section 2 — Shared Files

Members can upload files to the group and organize them into folders. Lecture slides, past exams, lab templates, study guides — anything useful to the group.

**Supported file types:** PDF, images (JPG, PNG), documents (DOCX)

**Folder structure:**
```
Shared Files
─────────────────────────
📁 Lecture Notes
   📄 Chapter 4 Slides.pdf
   📄 Chapter 5 Slides.pdf

📁 Past Exams
   📄 Midterm 2024.pdf
   📄 Final 2023.pdf

📁 Lab Reports
   📄 Lab 3 Template.docx

📄 Study Guide.pdf          ← loose file, no folder

─────────────────────────
[+ New Folder]  [+ Upload File]
```

**Creating folders:**
- Any member can create folders
- Folders are named freely (e.g. "Lecture Notes", "Past Exams")
- Files can be uploaded directly into a folder or placed loosely at root level
- Files can be moved between folders after upload

**Permissions:**
- Any member can create folders and upload files
- Only the uploader or group admin can delete a file
- Any member can create or rename folders
- Only the group admin can delete folders

**Smart prompt on upload:**
When a member uploads a file, Riven prompts:
```
Generate flashcards from this file?
[Yes, create a deck]  [Not now]
```
Tapping "Yes, create a deck" runs AI generation on the file and adds the resulting deck directly to Shared Decks. This closes the loop between uploaded notes and studying.

---

## Section 3 — Group Cram Session

A live study session where all group members go through the same deck simultaneously. One member starts it, others join, everyone crams together in real time.

**Starting a session:**
```
Start a Group Cram
─────────────────────────
Choose a deck:
◉ Ch. 4 Key Terms (42 cards)
○ Enzyme Functions (28 cards)
○ Preterite SER & IR (18 cards)

[Start Session]
```

**Joining:**
Active sessions appear at the top of the group page with a live member count:

```
🔴 LIVE  Group Cram — Ch. 4 Key Terms
         3 members studying now
         [Join Session]
```

Members can join at any point while the session is active.

**During the session:**
- Each member flips through cards at their own pace
- Simple response: Know it ✓ / Don't know it ✗
- A subtle live indicator shows how many group members are in the session
- No pressure to keep up — everyone moves independently

**End screen:**
When a member finishes, they see the group results:

```
Session Complete 🎯

Your results:     38/42 correct
─────────────────────────
GROUP WEAK SPOTS
Cards most people struggled with:

  ✗ What is the role of ATP synthase?
    3 of 4 members got this wrong

  ✗ Define substrate-level phosphorylation
    3 of 4 members got this wrong

  ✗ Difference between NAD+ and NADH
    2 of 4 members got this wrong

[Study Weak Spots]  [Done]
```

Group weak spots are calculated from all members' responses — cards that the majority of the group got wrong are surfaced automatically. Tapping "Study Weak Spots" launches a personal cram session with only those cards.

## Group Admin Controls

The group creator is the admin and has additional permissions:

- Rename the group
- Change the linked class
- Regenerate the join code (if shared too widely)
- Remove members
- Delete the group
- Delete any file or folder

## Database Schema

```sql
-- Groups
CREATE TABLE study_groups (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  class_id UUID REFERENCES classes(id),
  join_code TEXT UNIQUE NOT NULL,
  created_by UUID REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Members
CREATE TABLE group_members (
  group_id UUID REFERENCES study_groups(id),
  user_id UUID REFERENCES users(id),
  role TEXT DEFAULT 'member', -- member, admin
  joined_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (group_id, user_id)
);

-- Shared decks
CREATE TABLE group_decks (
  group_id UUID REFERENCES study_groups(id),
  deck_id UUID REFERENCES decks(id),
  shared_by UUID REFERENCES users(id),
  shared_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (group_id, deck_id)
);

-- File folders
CREATE TABLE group_folders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES study_groups(id),
  name TEXT NOT NULL,
  created_by UUID REFERENCES users(id),
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Shared files
CREATE TABLE group_files (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES study_groups(id),
  folder_id UUID REFERENCES group_folders(id), -- nullable for root level files
  name TEXT NOT NULL,
  file_url TEXT NOT NULL,
  file_type TEXT NOT NULL, -- pdf, image, docx
  uploaded_by UUID REFERENCES users(id),
  uploaded_at TIMESTAMPTZ DEFAULT now()
);

-- Cram sessions
CREATE TABLE cram_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES study_groups(id),
  deck_id UUID REFERENCES decks(id),
  started_by UUID REFERENCES users(id),
  started_at TIMESTAMPTZ DEFAULT now(),
  ended_at TIMESTAMPTZ,
  status TEXT DEFAULT 'active' -- active, ended
);

-- Cram session responses (for group weak spots)
CREATE TABLE cram_responses (
  session_id UUID REFERENCES cram_sessions(id),
  user_id UUID REFERENCES users(id),
  card_id UUID REFERENCES cards(id),
  knew_it BOOLEAN,
  responded_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (session_id, user_id, card_id)
);
```

## API Routes

```
-- Groups
GET    /api/groups                        ← all groups user belongs to
POST   /api/groups                        ← create a group
GET    /api/groups/:id                    ← single group details
PUT    /api/groups/:id                    ← update group (admin only)
DELETE /api/groups/:id                    ← delete group (admin only)
POST   /api/groups/join                   ← join via code
DELETE /api/groups/:id/leave              ← leave a group

-- Members
GET    /api/groups/:id/members
DELETE /api/groups/:id/members/:userId    ← remove member (admin only)

-- Shared Decks
GET    /api/groups/:id/decks
POST   /api/groups/:id/decks              ← share a deck
DELETE /api/groups/:id/decks/:deckId      ← unshare a deck

-- Folders
GET    /api/groups/:id/folders
POST   /api/groups/:id/folders
PUT    /api/groups/:id/folders/:folderId
DELETE /api/groups/:id/folders/:folderId  ← admin only

-- Files
GET    /api/groups/:id/files
POST   /api/groups/:id/files              ← upload file
DELETE /api/groups/:id/files/:fileId      ← uploader or admin only

-- Cram Sessions
GET    /api/groups/:id/sessions           ← active sessions
POST   /api/groups/:id/sessions           ← start a session
POST   /api/sessions/:id/join             ← join a session
POST   /api/sessions/:id/respond          ← submit card response
GET    /api/sessions/:id/results          ← group weak spots
```

## Real-Time Architecture

Group Cram Sessions require real-time sync. Supabase's built-in real-time handles this without a separate WebSocket server.

```js
// Subscribe to new members joining a cram session
const subscription = supabase
  .channel(`session-${sessionId}`)
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'cram_responses',
    filter: `session_id=eq.${sessionId}`
  }, (payload) => {
    updateGroupProgress(payload.new)
  })
  .subscribe()
```

## Build Order

Ship in this sequence — each step is independently useful:

1. Group creation and join via code
2. Shared Decks (add and study)
3. Shared Files with folders
4. AI deck generation from uploaded files
5. Group Cram Sessions (real-time, most complex)

---

## What Study Groups Is Not

- Not a chat feature — no messaging, no comments
- Not a social network — no profiles, no followers, no feed
- Not replacing personal study — individual SRS progress stays personal
- Not a homework submission tool — files are for sharing, not grading

The scope is intentionally tight. Study Groups is a focused academic collaboration tool, not a communication platform.
