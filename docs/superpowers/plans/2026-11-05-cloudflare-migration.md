# Cloudflare Hosting Migration Implementation Plan

**Goal:** Prepare and verify a Cloudflare preview of Riven before switching its domain.

**Architecture:** Serve the Vite SPA from Workers Static Assets, retaining Supabase services. Route `/api/*` explicitly to a separately verified Express-compatible Worker; never serve the SPA shell as an API response. Keep production DNS unchanged until authentication, API, AI, payments, PWA, and rollback are verified.

**Constraints:** Preserve uncommitted work; never put secrets in client assets. Do not run the server's automatic schema initialization against production during preview. Use the existing Supabase project; do not create another database. Avoid exposing private test endpoints or accessing real customer data for tests.

- [ ] Verify Express and its dependencies in a local Workers runtime with an isolated mock database, including `/api/csrf`, `/api/health`, headers, and webhook raw bodies.
- [x] Add and test preview Worker routing so `/api/*` cannot fall through to SPA HTML; test deep-link fallback and static files.
- [x] Build a preview with explicit production-safe client configuration (never localhost or development bypasses); verify required environment settings without printing secrets.
- [ ] Deploy to a Cloudflare preview, test login and core workflows, and confirm rollback. Inventory payment, OAuth, PWA, CORS, and iOS callback dependencies.
- [ ] Only after preview succeeds, configure production routing and custom domains, verify end-to-end behavior and retain a rollback target.

## Preview status

The preview is at https://riven-migration-preview.pmbodj49.workers.dev. Build it with `node cloudflare/build-preview.mjs`, then deploy with `npx wrangler deploy --config cloudflare/wrangler.preview.jsonc`. The build copies assets to a separate ignored directory and sets `X-Robots-Tag: noindex, nofollow`. The preview API intentionally returns 503 until a safe backend is ready. It uses the production Supabase project, so signed-in actions can change real account data.

The local Worker adapter now uses request-scoped pools, skips startup schema changes, supplies the trusted Cloudflare address to Express, and checks shared Durable Object rate limits. Against a disposable local Postgres database, health and CSRF succeeded, valid/invalid logins behaved as expected, and repeated login attempts were limited. A locally signed Stripe webhook was verified and recorded; an invalid signature was rejected. The server waits for webhook processing before acknowledging and uses async signature verification for Workers. Concurrent webhook processing and failure recovery still need review before moving payments.

The API Worker is deployed without a public route, with a service binding from the preview. Hyperdrive uses Supabase's session pooler, certificate verification, and disabled query caching. Production health and CSRF checks succeed. The preview forwards health, CSRF, account lookup, study assistance and shared-resource acceptance; unauthenticated access to the latter two is rejected. Other API endpoints stay closed pending review of legacy registration, password synchronization and account linking. All eight existing app users are linked to Supabase Auth and none uses legacy 2FA. Stripe's active webhook points directly to Supabase, and the frontend calls Supabase checkout/portal functions.

The Supabase `ALLOWED_ORIGINS` secret now explicitly includes the live and preview domains. The Supabase Site URL is `https://rivenos.com`; its redirect allowlist includes the live, www and preview origins while preserving the old entries. From the signed-in preview, the dashboard, note, deck library, deck creation form and existing mock exam loaded. A new River session was generated and answered a question after fixing the tutor's JSON response mode. Monthly and annual Stripe prices were verified as active and the preview build uses the recurring annual price. Other flows, including checkout, OAuth and PWA, still require verification. Do not switch the domain until the full preview is ready.

## Cutover update, November 6

Both domains are proxied through Cloudflare and have routes to `riven-production`. Their underlying CNAME target remains `b003ebd48783604b.vercel-dns-017.com`; both `_vercel` TXT records remain for rollback. Removing the two Worker routes returns requests to Vercel through Cloudflare. An initial cutover exposed a stale-service-worker failure when old hashed JavaScript was absent. The production build now retains the previous Vercel release's public assets in `cloudflare/legacy-assets/assets`; `build-preview.mjs` copies them into each build. Keep this directory when deploying while old clients may still be active. Missing assets now return 404 rather than SPA HTML. HTTP health, deep-link, old-asset and missing-asset checks pass. The owner confirmed the signed-in dashboard loaded after a refresh. Some browsers that cached a bad asset during the first attempt may need their Riven asset cache cleared.

Annual Stripe checkout was verified without payment and the owner free simulation was restored. Google OAuth authorization redirects were checked but full Google sign-in remains unverified. The Supabase security advisor's publicly accessible table finding was fixed, and direct API access to internal push notification helpers was revoked. The database's intermittent cron startup timeouts and disk I/O warning remain under investigation; don't interpret a successful cron enqueue as proof the downstream function succeeded.

November 6 follow-up: registration now surfaces Supabase errors and handles email confirmation without calling the disabled legacy registration route. When the legacy bridge is disabled, failed email login reports the Supabase error; a live invalid-credential test displayed it correctly. Profile lookup and user search RPCs now require an authenticated role. The owner reported the live dashboard works after a refresh. A complete new-account email-confirmation test and full Google sign-in still need an appropriate test account. At last inspection the scheduled jobs had run without startup errors for over two hours, but the root cause and disk I/O budget had not been confirmed resolved.

The audio retry cron retains its one-minute schedule but now skips the HTTP call when no note-enhancement jobs are queued or running. A live empty-queue run succeeded with `0 rows`; recovery-eligible statuses were checked separately. This avoids unnecessary Edge Function calls and HTTP response writes, but the underlying intermittent startup timeouts and historical log/table growth still require monitoring.

Later November 6 security review: 39 of 40 mutable function search paths were pinned; the remaining signup trigger was excluded because new-account verification was deferred. The remaining anonymous definer warnings cover RLS helper functions and trigger functions, so their grants were retained pending policy-by-policy review. Production logs show successful deck, guide, exam, note-enhancement, and tutor calls in the last day, but the HTTP status alone does not validate their generated content.
